# 実装計画（第1〜6段階）

前提：`docs/asset_audit.md` の監査結果。各段階を「実装 → 検証 → 報告 → ユーザー承認」の順で進め、承認を得るまで次の段階に進みません。`main` へのマージと Pages での公開も、承認を得てから行います。

## 素材の取り込み方針（決定済み。第1段階の冒頭で実施）

- 元素材はリポジトリに入れない（ユーザーがバックアップとして管理）。`scripts/build-assets` に元素材フォルダのパスを引数で渡し、`docs/source_checksums.txt` で照合してから、採用する素材だけを `public/assets/` に出力する。
- 画像：原寸1448×1086を保ち、sharp か cwebp でWebP化する（PSNR 40dB以上と目視確認）。SVGは補修後に `public/assets/svg/` へ置く。
- 音声：20個を再エンコードせず、そのままコピーして `public/assets/audio/{bgm,ambient,sfx}/` に置く。`audioRegistry.ts` とマニフェストの照合テストを用意する。
- 公開しない素材は `docs/asset_audit.md` §6.2 のとおり。
- Viteの `base: '/nazotoki/'`。素材のURLは `import.meta.env.BASE_URL` を基準にする。

## 第1段階：起動できる土台と4方向の探索
- Vite + React + TS、ESLint/Prettier、Vitest、Playwright の雛形。`base: '/nazotoki/'`（変更可）。
- 画面遷移：タイトル → オープニング（手紙）→ 探索 → 拡大画面（中身は空でも、戻る操作が動くもの）。
- `SceneView`：4:3の座標系、`contain` の余白補正、相対座標のホットスポット、左右の矢印と横スワイプ、目アイコンによる強調。
- 背景は**仮背景**を表示し、画面上に「仮」の表示を出す。南の閉扉と西面は、補修が済むまで「仮背景（不足）」と明示します。
- インベントリと手帳の枠、設定（音量の欄だけ）。
- 合格：375×667とデスクトップで、すべてのボタンが意味のある動作をする（Playwrightで確認）。

## 第2段階：5問とアイテムのルール
- 純粋関数：`isBookOrderSolved`, `isPaintingCorrect`, `countTrueDrawers`, `isClockSolved`, `isDoorSolved`。
- 状態モデル：カードの所在を `unfound | revealed | inventory | slot[n]` の1か所だけで管理（消失も複製もしない）。
- 操作：ドラッグとタップ選択の両方、時計とダイヤルの±1分、スロットからインベントリへ戻す操作。
- 扉装置SVGの補修：縦長4枠、動的ダイヤル、DOMで文言を表示。
- 合格：本24順列、扉24順列×時刻×不足、解く順序24通り、机、時計の自動テストがすべて通る。

## 第3段階：ヒント・任意調査・自動保存
- 確定ヒント15本、探索サポート、O1〜O6、2枚目と4枚目のイベント。
- `saveVersion`、マイグレーション、破損の検出とバックアップの選択肢、第2章キーの保護、表示中の時間だけ計測、解錠時にクリア時間を固定、クリア後の再調査。
- 合格：途中の各状態でリロードしても、消失・複製・途中フレームへの復帰が起きない（Playwright）。

## 第4段階：ビジュアルの整合と音声
- 背景の補修（P0/P1）：北の空きスロット、東の針のマスク、西の窓の修正、南の閉扉ベースと可動扉、書斎Bの差分。**新しい画像生成が必要な場合は、その時点で報告し承認を得ます。**
- 音声20種の接続、BGMの排他再生とクロスフェード、雨音とold_houseの制御、カテゴリ別の音量とミュート、非表示タブでの停止、iOSの解錠処理。
- 合格：画像と謎に矛盾がなく、20個すべての再生経路をテストで確認。

## 第5段階：エンディングとクリア後
- 約7秒の解錠演出 → 「先へ進む」 → 暗闇の扉（door_open）→ 通路 → 書斎B → 00:14 → 「第1章 完」（約28秒）。
- スキップ、字幕、Reduced Motion、非表示時の一時停止、リロード時は冒頭から再生、再鑑賞。

## 第6段階：最終QAと公開準備
- Vitest/Playwright/ビルド、静的アセットとリンクの検査、⑮チェックリストの照合（実施した項目にだけチェックを付ける）。
- GitHub Actions による Pages デプロイ。差分・URL・確認事項を提示してから、マージと公開を行います。
- iOS Safari の実機テストは、この環境ではできないため「未実施」と明記します。
